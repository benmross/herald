What these records mean

session_meta saves session setup and base instructions. task_started marks a turn answering a message, not a shell command. turn_context saves model and permission settings for that turn.

The provider may log the same message as both a conversation record and an item-completed notification. Captures also save launch inputs separately. Those are overlapping records of the work, not proof of repeated model calls or extra copies in the prompt. Herald can supply instructions on later turns too; this view groups identical instruction blocks when it can verify an exact match.

A turn includes the original request and any messages you send while it is active. Those extra messages are shown as steering updates. Tool results can carry a user role in provider logs; they are not messages from you and do not start turns.

Context is the size of a model input at a measured step, including cached input. It is not elapsed time or total tokens processed. Full payloads can therefore look repetitive even while context stays roughly flat. Missing history, upstream truncation and hidden reasoning cannot be recovered.
